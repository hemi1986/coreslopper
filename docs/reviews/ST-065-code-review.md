Security pass (no findings):
- **DOM injection:** all user and server data reaches the page through `el(..., { text })`, text nodes or `setAttribute`: names, ids, `e.message`, `swUnknown(id)` and angles. `innerHTML` is only ever set to `''`. The links are `#/sets/<id>` with a fixed hash prefix, so no `javascript:` URL is possible. The ids come from the route regex `[a-z0-9][a-z0-9_-]*` or from the server's slug.
- **Encoding:** the upload URL is built as `encodeURIComponent(id)`, `name`, `angle` and `plate`. Only `role` is a constant.
- **File types:** `accept=".png,.jpg,.jpeg,.webp"` is only a hint in the browser. The server path is unchanged (`SET_LIBRARY_ROUTES.uploadFile`: temp folder, `safeName`, size limit, `addLibrarySetFile`), so no new trust lands in the client.
- **CSRF and routes:** no new route. The JSON posts and uploads go through the existing board handler with its origin check.
- **ST-064 retry fix:** it still holds. `sendLibraryFiles` filters `sent` by `File` before the chain and adds a file only after its upload succeeded. The character wizard keys by `item.file` (comment at character-wizard.js:74) and its `failOnce` test passes. The set refs keep one `refsSent` per page. The plate uses a fresh `Set`, which is correct because it is one file and a refused one has to be sent again.
