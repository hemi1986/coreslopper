Checked and found sound:
- **Cue.** It is measured from the trimmed start, and `librarySoundTimeProblems` checks `cue <= trim.end - trim.start`. This matches the glossary's Sound Cue, the data model ("seconds from the trimmed start, inside the trim") and the consumer ST-012 ("relative to the trim's start").
- **Temp folder.** It sits in the same file system as the target, so `rename` is atomic. It is cleaned up in `finally`, skipped by `storedHashes` (the id regex refuses a leading dot), and gitignored. `git check-ignore` confirms that `.incoming-*/sound.yaml` is not re-included by the negation.
- **Id.** `checkId` and `slugOf` give only `[a-z0-9_-]`, so the id cannot traverse paths.
- **Conversion.** It applies no gain and no normalisation, keeps the channel layout and strips metadata.
- **Domain rule placement.** The time rule sits in core and is applied both in the command and in the schema's `superRefine`.

**Verdict: fix blockers first.**
The most important finding is #1: every sound shorter than about 0.4 s is refused as "silent", because integrated loudness is undefined for it.

## Resolution (main session)

- #1 fixed: a sound shorter than 3 s is measured looped (`measureLoudness(file, loops)`); the stored WAV is untouched. Test: a 0.2 s click.
- #2 fixed: the entry also records `original_hash` (the file as added); a duplicate matches either hash, so another ffmpeg build still finds the same file.
- #3 fixed: ffmpeg reads `file:<absolute path>` with `-protocol_whitelist file`.
- #4 fixed: an object trim without an end is `invalid`.
- #6 fixed: the test helper lists every folder, so a leftover `.incoming-*` fails the tests.
- #9 fixed: `SoundRefused.sound` carries the refused id once it is known.
- #10 fixed: `LIBRARY_SOUND_ENTRY` names `sound.yaml`.
- #11 fixed: a lost rename race is refused as `id-taken`.
- Acceptance question "silent is not-audio" fixed: a silent file is refused as `silent`.
- #5 skipped: the text, tag and slug helpers mirror `character-library.ts`; folding them belongs with the set library (ST-023 ff.), which needs the same helpers – one shared module then, not now.
- #7 skipped: the `unknown` input types are for the board route (ST-018), kept so the route needs no second parser.
- #8 kept: `added` mirrors the character library's `added`; it is bookkeeping, not domain data.
