## Remarks
- The scenario tests enter at `addLibrarySetFile`, the function `set add-file` calls, which the seam catalog names explicitly; commander itself is not automated (the same as ST-024 and the character library). I checked the command end to end in a temp workspace root: success, plate without angle, `--role photo`, gif, `--angle` on a ref, missing set id, explicit `--plate wide`, a taken plate id with another image, the same plate id with the same image, and a 513 MB file — all behave as the story's rules say.
- Scenario 3's *Given* (`neon-bar` has the reference `bar.jpg`) is produced by the command under test rather than pre-seeded on disk. It genuinely establishes the state and the *Then* still pins the dedupe (`refs` and the folder listing), but a fixture that writes `bar.jpg` and a `set.yaml` directly would keep the *When* as the only use of the SUT.
- The story's four scenario slots are spent on the angle, the type and the content dedupe; the 512 MB rule and the plate-id uniqueness are implemented and behave correctly (verified by hand) but have no scenario or test. Not a defect — a coverage question.
- Commit `b482030` lands all four ST-025 tests at once, including the gif test that only goes green in `1b70c02`; traceability is by title and `verify.ts`, so this has no functional effect, but the commits do not read one-scenario-at-a-time.
- `--role` defaults to `ref` in the CLI although the Context writes `--role ref|plate`; the default is user-friendly and the domain function still rejects any other value.
