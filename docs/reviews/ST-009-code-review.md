## Bug-focused pass (shared platform code)

- **Episode scripts**: For an episode, `scriptCanon` passes `kind: 'episode'` and the series bibles. The hook's episode branch keeps its "characters.yaml/sets.yaml is missing" errors. `placeLines` and `takeSource` behave the same for prompted effects. The 30-second check and the ids-only fallback are gated on `meme`. No regression found beyond the wording in #7.
- **Take hashes of existing generated sfx takes**: `takeSource` still returns `{ kind, prompt, duration }` for a prompted effect. `hashObject` drops `undefined` keys and sorts keys (`packages/core/src/hash.ts:30-40`), so existing take hashes stay the same. The separately committed characterization test (9ab2139) pins the shape. A literal hash of the demo effect would pin it harder, but the current test is sufficient.
- **Type narrowing**: There are three places where `duration`/`prompt` might be undefined. `voice-track` checks for `sound` before `prompt` and guards the `sfxMax` comparison, `placeLines` throws on a missing duration, and `knownLineSeconds` returns `undefined`. A grep finds no other reader of `line.duration`/`line.prompt` on sfx lines. The non-null assertion in `tests/series-characterization.test.ts:65` is justified: the demo effect has a duration, and the type change is the only reason for it.
- **Before and after style-character (HS-262)**: Before `style-character`, the hook and `validate` check speakers and sets as ids. After it, they check against the meme's own bibles, as soon as the files exist (see #6). `voice-track` and `episode-track` still require both bibles. That is consistent with the stage order.
- **Touched tests**: The `series-characterization` change is justified. The `meme-kind` change is justified as an update to the new behaviour, but it took away the only coverage of episode-track's hard stop (#1).
