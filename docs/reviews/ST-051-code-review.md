# Code review – ST-051: The release shape is kept once the release has started
Base: marathon/2026-11-28 · Commits: 3 · Date: 2026-11-28

The scope is `packages/core/src/release.ts` (`releaseStart`, `keptShapeProblem`), `packages/cli/src/release.ts` (the guard in `buildRelease`) and `tests/release-shape.test.ts`. A second, bug-focused pass covered the release lock, the order of reading the status against writing and rendering, manifests without a shape, and the board's quick refresh. `tests/release-shape.test.ts` is green (13/13). `check-language.ts` is OK.

What holds up:
- The guard runs after `loadProject`, `releaseShape` and `usedLibrarySounds`, which only read. It runs before `mkdir`, every render, `writer.place`, `planCalendar` and the manifest, so a refused run writes nothing and renders nothing.
- `withReleaseLock` is not re-entrant, but no caller holds it around `buildRelease`. The board's `scheduleRefresh` runs after `updateStatus` has released the lock, and the autopilot never calls `buildRelease`. No deadlock.
- A manifest without `shape` falls back to `kind` through `manifestShape`, the same fallback `release-facts.ts:138` uses for the board. A pre-ST-047 vertical episode of 180 s or less therefore counts as having started as `episode`. That matches its folder, which has the episode layout.

## Round 2
Base: marathon/2026-11-28 · Commits: 8 (fixes 0aa5712, b046520, cd79f2a) · Date: 2026-11-28

A bug-focused pass over the whole diff. `tests/release-shape.test.ts` is green (17/17). `check-language.ts` is OK.

How the round 1 findings stand:
- #1 (merge blocker, rule-bypass) is fixed. `releaseStart` skips every key that contains `#`. Calendar event ids never contain `#`: they are fixed names (`youtube`, `tiktok`, `instagram-post`, …) or `short:<name>:<platform>`, and a Short name must match `^[A-Za-z0-9][A-Za-z0-9_-]*$` (schema.ts:896). So only checklist keys (`checklistKey`, release-records.ts:34) are skipped. The new test ticks `youtube#synthetic content disclosed`, cuts the track to 190 s, and checks the manifest's shape `episode`.
- #2 (major) is fixed. When the manifest exists, cannot be read, and the release started, the run throws before `mkdir` and writes nothing. The test compares a snapshot of the folder. Before the first post, the lenient rebuild stays, and a test covers that too.
- #6 (minor) is fixed. The doc comment now says "first in the status file's key order", and a test covers an older manifest without `shape`. That test checks both the refused run and the run with the same shape.
- #3, #4 and #7 were skipped on purpose and stay minor. #5 stays an open question for the developer.
