## Edge cases not covered by the story

| Case | Expected by a rule? (cite) | Recommendation |
|---|---|---|
| A library file named in `set.yaml` is missing on disk | Consistent with the refusal rule ("nothing is copied" on `EVT-LibrarySetUseRefused`); probe: `useSet` rejects `library files of bar are missing: start.png` before writing anything, leaving no `sets.yaml` and no `sets/bar`. | no action — behaviour is safe; add a regression test only if this refusal is meant to be promised |
| The target already has set `bar` linked to a different library id (`library: other-bar`) | Yes — story Context/ADR 0052: a target set of that id that is not linked to *the* entry refuses the use. Probe: refused, `sets.yaml` byte-identical, no files copied. The message says "has its own set" although the set is linked elsewhere. | question — refusal is correct; consider a clearer message ("is linked to another library set") when the board or docs surface it |
| The target is neither a project nor a series canon | The command's entry rule (`set use` targets a music video or series canon); probe: refused with "neither a project nor a series canon", nothing written. Same guard as `useCharacter`. | no action |
| A library entry has a plate without an image (`file` absent) | No rule states it. `LibrarySetSchema` allows it (imports may report a missing file and keep the plate, ST-026). Probe: `useSet` succeeds and writes the plate without a `ref`; `files: []`. The target then has a plate it must generate, the cost ADR 0052 wants to avoid. | question — decide whether a fileless plate should come along without a ref, be warned about, or be refused like a missing library file |
| The target is a meme project | Not named in the story. `useSet` accepts it (probe: `kind: meme`, files copied, `sets.yaml` written); BC-Bibles' purpose includes memes, and `useCharacter` allows memes too. | question — confirm memes are an intended target (the wizard documents music videos and series only) |
| A second use after the target's plate file was deleted | The rule says a second use adds what the target lacks. Probe: the file `sets/bar/plates/counter.png` is restored while the plate stays once in `sets.yaml`. | no action |
| The target's `sets.yaml` is already schema-invalid (e.g. duplicate plate id) when the use lands | No rule names this third failure mode; the two event-refusal reasons are episode and own set. Probe: the command refuses with `sets.yaml would be invalid: duplicate plate …`, leaves `sets.yaml` unchanged — but the copied `sets/bar/` files remain. The normal path cannot produce an invalid bible (hook-validated), and `useCharacter` copies before validating in the same way. | question — low; consider staging the copies and rolling back like `importSets` if orphan files matter |
| A positive series-canon target (`set use <canon> bar --series`) | Yes — the story's title and Context promise "a music video or series canon", and the episode rule sends the user to the series. No scenario/test covers the positive series path. Probe: both `useSet` on a real `createSeries` canon and the real CLI `set use night-desk bar --series` succeed, writing `sets.yaml` with `library: bar` and the files. | question — the implementation works; decide whether the missing positive series scenario is a spec gap to close before `done` |
| Two uses into one target, or into the library, at the same time | No locking rule; library and bible writes are atomic but unlocked (known gap G-130, `docs/engineering/conventions.md`, "Commands and events"). This command adds no new lock. | question — covered by the existing workspace-wide gap; no action in this story |
| Long texts and the other language | Library fields allow up to 4 000 characters and are copied untruncated; CLI output is English only by convention. | no action |
| A same-id plate in the target with a different image | The story only promises adding what is missing; probe of the delete case shows the file is restored, and an existing plate id is never duplicated (uniqueness invariant holds). Changing a target plate's image is not part of this command. | no action |
