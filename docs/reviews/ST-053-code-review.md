# Code review – ST-053: A short episode's YouTube post asks for the series playlist
Base: marathon/2026-11-28 · Commits: 3 · Date: 2026-11-28

Security pass. A `series.yaml` value cannot reach the DOM as HTML. `el()` in `packages/cli/src/board/lib.js` sets `text` with `textContent` and appends string children as text nodes, so the label (which holds the playlist title) and the link text are always text. The href guard `/^https?:/` is anchored and case-sensitive. That rejects `javascript:`, `JAVASCRIPT:`, `data:` and a leading space, so a non-http(s) href cannot be set on the board. Zod 4's `.url()` also trims a leading space before the value is stored. The link opens with `target="_blank"` and `rel="noopener"`.

Malformed input. `youtube_playlist: null`, a string, `url: 5` and `title: null` all fail `SeriesSchema`, and `readYamlFile` turns that failure into a `ValidationError`, not a crash. I checked this by running each value through `SeriesSchema.safeParse`.

Checks run: `tests/release-series-playlist.test.ts` passes (5 tests), and `check-language.ts` passes.

**Verdict:** ready to merge
The single most important finding is #1: the schema accepts non-http(s) playlist URLs (`javascript:`, `data:`), and the release check reports them as PASS. The board is not exploitable, but the scheme belongs in `SeriesSchema`.
