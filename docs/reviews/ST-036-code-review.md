Bug-focused pass over the release path (no findings beyond the table):
- `runRelease` returns before `buildRelease`, so for an internal project nothing is removed, cleaned up or rendered. An earlier folder stays exactly as it was. The CLI action (`index.ts:323`) ignores the return value, so the run exits with 0 and `qa-export` stays green.
- `quickRelease` reads `project.yaml` before the dynamic import. An invalid `project.yaml` now fails earlier, and `scheduleRefresh`'s catch logs it as before.
- `--replan` and `--no-render` are ignored without a message on an internal project. That is acceptable: nothing gets planned.
- The schema field is optional with no Zod default, and `releasedPublicly` treats unset as `public`, which matches the glossary. `schema/project.schema.json` is regenerated. `check-language` is clean, and the 3 scenario tests pass with the exact titles.

Verdict: ready to merge
Most important: an internal project still gets a release calendar through `calendar <project>` and through an approval (finding 1). Decide whether to guard `runCalendar` in this story.

## Resolution (main session, 2026-11-22)

- Q1 calendar by other commands: fixed as recommended – `runCalendar` refuses an internal project (covers `calendar <project>` and the approval's replan); test added.
- Q2 earlier calendar read as live: not built here; row in `docs/stories/OPEN_QUESTIONS.md` for the user (widens the story).
- Minor 3 three checks: kept – `runRelease` reports and exits 0, `quickRelease` skips silently, `buildRelease` refuses as a guard for direct callers (now tested). Returning a "not released" result from `buildRelease` would change its return type for every caller and test; not worth it for one story. The double parse of `project.yaml` is cheap.
- Minor 4 weak scenario 2: fixed – the other project now has a `project.yaml`.
- Minor 5 board refresh untested: skipped – `quickRelease` is a private two-line guard; the seam (`boardHandler` with a status change) needs a full board fixture for one early return.
- Minor 6 heading clash: fixed – the conventions heading is now "Packaging (workspace slice)".
