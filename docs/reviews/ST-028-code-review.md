## Bug-focused pass over `useSet` (no further findings)

- The two refusals happen **before** anything is copied or written: the episode check (:339-347), the target check
  (:345-346) and the clash check (:360-363) all precede `copyByContent`. Both refusal tests therefore observe a
  clean target, and the story’s “nothing is copied” holds on those paths.
- The library id reaches the filesystem only through `loadLibrarySet` → `libraryEntryFile` → `checkLibraryId`
  (`isScriptId`, ≤ 80 chars), and the entry’s file names go through `LibraryFileSchema`
  (`^[a-z0-9][a-z0-9._-]*$`), so neither can traverse out of the entry folder. No personal data reaches the log;
  the CLI prints the id, the target’s basename and counts.
- The rules hold: refs and every plate always come along (no option to drop one), the id is the library id, the
  set carries `library: <id>`, a second use appends only what is missing (content dedupe via `copyByContent`, path
  and plate-id dedupe in the node), plate ids are appended only after the entry’s own uniqueness check, and
  `SetBibleSchema.safeParse` runs before the write. No `new Date()`, no clock, no time-based rule. Scope is clean:
  the board page, the wizard step and the skills are untouched, and `UseSetResult` carries no speculative fields.
- The `<target> <id>` wiring matches `character use` line for line, including `--series`; the seam catalog row
  gains `useSet` correctly.

Verdict: **ready to merge** once findings 1 and 2 are fixed — 0 blockers, 2 majors, 7 minors, 1 question.
Most important: the use copies before it validates and writes, without staging, so a failed run leaves
`sets/<id>/` files no `sets.yaml` names (finding 1) — stage the copies and commit them after the write, as
`importSets` already does.
