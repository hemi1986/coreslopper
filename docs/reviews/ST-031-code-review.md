# Code review – ST-031: Delete a library set

Base: main · Commits: 2 · Date: 2026-11-24

Checks run at HEAD `1dada69`: `npx vitest run tests/set-library.test.ts` → 59/59 green; `npm run typecheck` → green;
`check-language.ts` → “Glossary language OK”; `check-scenarios.ts ST-031` → 2/2 scenarios, exact titles;
`lint-story.ts` → green. The two scenario tests enter at `removeLibrarySet`, the function the seam catalog names
(“Set library” row, `docs/engineering/conventions.md:238`); the two CLI tests enter at the command, which the
“Command” row of the same catalog allows (`conventions.md:221`). The *Then*s are checked with literals and a
byte-for-byte copy of the production’s `sets.yaml`, so the tests are neither tautological nor coupled to internals.

The implementation follows `removeLibrarySound` (`sound-library.ts:281-307`): validate the id, decide presence by the
folder, rename into a hidden `.removing-*` in the same parent, then `rm`; the entry is reported as deleted before the
long delete, so a failed `rm` can only leave a hidden leftover. ADR 0052 is honoured: only `library/sets/<id>/` is
touched, productions keep their files and their `library: <id>` (the test asserts both), and the broken-entry and
leftover cases are covered by tests. The overloading of `set remove` is safe: Commander 14 rejects `set remove bar
counter.png` (excess argument) and a valueless `--file`, so a missing option cannot silently become a full delete.

Security pass on the destructive path: `checkLibraryId` (`library-entry.ts:35-38`) runs before any `existsSync` and
accepts only `isScriptId` (lowercase, no `/`, no `\`, ≤ 80), so `../bar`, `/etc` and `Vine Bar` are refused — tested. I
verified the rename+`rm` behaviour outside the suite: a `library/sets/<id>` that is a symlink to a folder outside the
workspace is unlinked, and symlinks *inside* the entry are unlinked without following them (the target files
survive); the `.removing-*` name cannot be addressed as an id because a leading dot fails `isScriptId`. No personal
data, no network, no public output.
