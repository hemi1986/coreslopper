Bug pass over the shared validation path. No defects found:
- **Path detection:** `isLibrarySoundFile` checks `<…>/library/sounds/<id>/sound.yaml` on the resolved path. The hook's `inLibrary('sounds')` is the same check. A `sound.yaml` anywhere else exits early (verified by hand), so no project or series lookup runs for it and nothing that worked before now fails.
- **Ordering:** the library check runs before `findArtifactRoot`, the same as for library characters, so a library entry never hits "No project.yaml or series.yaml found". A `projects/<p>/library/sounds/<id>/sound.yaml` would be taken as a library entry, but no layout or ADR creates such a path.
- **Hook early exits:** `TRACKED` gains `sound.yaml`. A `sound.yaml` outside a library is dropped by the extended `character.yaml`/`sound.yaml` guard before `findArtifactRoot`. `isChannel || isLibrary` skips the project lookup as before. Library characters behave as before (the rename `characterDir` → `entryDir` changes no behaviour).
- **Schema messages:** `title` and `use_when` now carry custom `min(1)` messages. `LibrarySoundSchema` is not in `scripts/generate-schema.ts`, so `schema/` is unaffected. Its only other callers are `loadLibrarySound`, `addLibrarySound` and `updateLibrarySound`, which check title and use when with their own `SoundRefused` text first ("a library sound needs a …"). The schema message now matches that text, and the existing ST-001/ST-002 assertions (`/needs a title/`, `/needs a use when/`) still pass.
- **Import cost:** `validate-file.ts` now imports `sound-library.ts`, which pulls in `episode-track.js` and `media.js` on every hook run. There is no cycle and no side effect at load time, so nothing to fix.

Verdict: ready to merge
Most important finding: #1, the shipped `workspace/CLAUDE.md` hook list (and the hook's header comment) leaves out `library/sounds/<id>/sound.yaml`. Separately, #6 needs the user's decision: the hook checks agent edits only, not the user's own saves, which is what the story's "As a user" sentence promises.
