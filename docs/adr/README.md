# Architecture Decision Records

Short records of decisions that are hard to reverse, surprising without context, and the result of a real trade-off.

| ADR | Decision |
|---|---|
| [0001](0001-folder-based-projects.md) | Projects are folders in one workflow repository; export is optional. |
| [0002](0002-autonomous-pipeline.md) | The pipeline runs autonomously with automated QA; no creative approval gates. |
| [0003](0003-stage-isolated-execution.md) | One fresh context per stage; files are the only interface. |
| [0004](0004-zod-schema-source.md) | Zod is the schema source; JSON Schema is the cross-language contract. |
| [0005](0005-symbolic-timing-anchors.md) | Storyboard timings use symbolic anchors resolved from effective timing. |
| [0006](0006-fal-adapter-cache-budget.md) | Narrow provider interface, fal.ai first, hash cache, budget guard. |
| [0007](0007-remotion-deterministic-renderer.md) | Remotion is the renderer; determinism is enforced. |
| [0008](0008-local-audio-analysis.md) | Local Demucs + WhisperX + librosa; lyrics text wins. |
| [0009](0009-mit-open-source.md) | MIT open source with explicit third-party notices. |
| [0010](0010-npx-onboarding.md) | npx onboarding with a versioned runtime snapshot. |
| [0011](0011-higgsfield-provider.md) | Higgsfield as a second provider; per-project provider selection and role alternatives. |
| [0012](0012-workspace-update.md) | `coreslopper update` merges a new runtime against a recorded baseline. |
| [0013](0013-existing-song-interactive-setup.md) | Every project starts from an existing song; `new-video` runs setup, brief, and treatment interactively. |
| [0014](0014-comfyui-local-video.md) | ComfyUI as a local video backend driven by tagged API workflow exports. |
| [0015](0015-comfyui-images-lipsync-audio.md) | Superseded by 0017. ComfyUI also for stills, edits, lip-sync, and audio; output kind from the `cs_output` node. |
| [0016](0016-episode-projects.md) | Episode projects: a project kind with its own stage list, a series canon, and an episode track built from a script. |
| [0017](0017-ltx-lipsync-flf2v-official-templates.md) | Local lip-sync on an LTX FLF2V lip-sync workflow; all other clips on the official LTX templates; no negative prompts. |
| [0018](0018-thumbnails.md) | `qa-export` makes three thumbnails: the agent picks stills and words, a Remotion still composes the pixels. |
| [0019](0019-release-package.md) | `qa-export` ends with a release package: three Shorts with vertical thumbnails and one upload text, checked by `qa`. |
| [0020](0020-model-bench.md) | A model bench in `bench/`: fixed cases from past projects, rendered on named targets, scored by rubric and by the user. |
| [0021](0021-topview-provider.md) | Topview as a third cloud adapter for stills and clips; one endpoint pattern, two request formats, no lip-sync. |
| [0022](0022-review-player.md) | Superseded by 0050. A review player writes frame-accurate notes on renders to `review/notes/`; outside the pipeline, read on a fix pass. |
| [0023](0023-publish-command.md) | `publish` is a user command, not a stage: YouTube private or scheduled, TikTok inbox drafts, from `upload.yaml`, idempotent by file hash; no Instagram, no MCP. |
| [0024](0024-release-folder-manual-distribution.md) | `release` builds one folder `renders/release/` with every file and text to publish; distributor facts only from the user; manual distributor upload, API distributors later. |
| [0025](0025-plates-props-character-states.md) | Plates (empty set frames per camera angle), prop references, and character states are reviewed references that shots name in `refs`; keyframes in a plate are edits of it; music videos may have `sets.yaml`; episodes only append to the canon. |
| [0026](0026-cloud-lipsync-and-lead-only-audio.md) | Higgsfield (Speak v2, legacy job-set routes) and Topview (Avatar 4 on the OpenAPI) lip-sync; `generate --lipsync-provider`; lip-sync segments are lead-only: backing words and `--mute` spans are silenced, `lead.wav` is preferred, unwritten vocals are reported. |
| [0027](0027-pika-lipsync-audio-guide.md) | Local lip-sync on Pika H3 Ref2VA with the vocal anchored from frame 0 (`MiniMaxH3AddGuide`), `pika-h3-ref2va-lipsync`; LTX lip-sync stays as a `params.workflow` fallback. |

| [0028](0028-release-board-and-calendar.md) | `release-board`: a local page per project and platform (files, texts, limits, settings, live URLs, done state); `review/calendar.yaml` planned under the workspace's `config/release-schedule.yaml` without collisions across projects; X, LinkedIn (agent decides), announcement, and microsite in the upload data. |
| [0029](0029-release-autopilot.md) | One approval on the release board hands a release to the autopilot: `release-run` (on a timer) posts each calendar event a platform API can post, at its time — YouTube ahead and private until the audit, Instagram, X, LinkedIn, TikTok drafts, the links step, the microsite; never twice, a stuck post waits for the user. Nothing goes public without the user's approval. |
| [0030](0030-board-as-hub.md) | `board` (alias `release-board`) is the workspace's hub: a read-only production view of every project and series (stages, budget, queue, verdicts, documents, renders) with the next Claude Code command from one pure function, beside the release view; project files from a whitelist; static ES modules, no build. |
| [0031](0031-watchdog-and-board-container.md) | `watch`: one round of `release-run` and a production scan that records events (stages, renders, queue, budget) and stalled stages in `.cache/watch/`; `render` writes `review/progress/`; the board container (`compose.yaml`) runs the board and the round every five minutes on any OS, with `node_modules` in a volume, host-aware locks, and `.env` read again each round. |
| [0032](0032-web-review-rounds.md) | The board's review view: frame-accurate player with a timeline of sections, shots, and notes (frame or range) in the desktop player's notes format; one click sends drafts as a frozen review round (`review/rounds/<NNN>.json`, with shots and section); the agent answers each note in `<NNN>.replies.json`; `/video-next` answers open rounds first. Amends 0022. |
| [0033](0033-board-wizard.md) | The board's wizard (**+ New**) for a music video, series, or episode: project data, lyrics with deterministically proposed section tags, song and stem through `import-song`, and user references (`references.yaml`, files in `assets/references/`); it ends with `/new-video`, `/new-series`, or `/new-episode`, which grill from there; shared with the CLI (`lyrics`, `reference`); streamed, size-limited, same-origin uploads. |
| [0034](0034-character-library.md) | The workspace character library (`library/characters/<id>/`): characters of finished style-character stages and canons come in by themselves, or by `character import` / `new` and the board; one entry per character, files stored once by content; `character use` copies identity and chosen states into a music video or canon with `library: <id>`, and the character bible builds on it. |
| [0035](0035-series-in-projects.md) | Series canons live in `projects/<slug>/` beside their episodes (`series.yaml` marks them); one slug namespace; episodes reach the canon at `../<series>/`; `migrate-layout` moves old workspaces, `doctor` and `update` remind until it ran, and `update` adds no copy of a canon still in `series/`. |
| [0036](0036-workspace-payload.md) | The workspace payload is separated from the engineering layer: `workspace/` becomes the workspace root, the root `AGENTS.md`, `CLAUDE.md`, and `.claude/` are for working on the repository and never ship; `scripts/runtime-files.mjs` classifies every tracked file; the media workflow is tried in a sandbox workspace. |
| [0037](0037-board-wizard-completes-setup.md) | Proposed: the board wizard may complete the `setup` stage through core's transition, and does nothing else to a project's state; the production view stays read-only. Amends 0030 and 0033. |
| [0038](0038-generation-queue-and-verdicts.md) | Proposed: one generation queue per project and one run at a time; attempts as files, only an approved one filed; the art director judges headless with a JSON verdict, in the background; only a blocking defect fails; images requeue themselves with the fix prompt, clips wait; at most three local and one cloud attempt; every verdict in `verdicts.jsonl`; a region patch is an attempt; the user's accept is final. Amends 0002. |
| [0039](0039-song-timing.md) | Proposed: one effective timing merged and checked on every load (`timing.effective.json` is a snapshot); overrides move times only and are entered at the user's request; word anchors carry an edge; section ids from the tag text; the Python analysis validates against the generated schema, analyzes the user's vocal stem and never replaces it, and stops on a missing model; words in parentheses are backing vocals. Amends 0005 and 0008. |
| [0040](0040-storyboard.md) | Proposed: one storyboard model for both project kinds, checked as a whole by core; coverage within one frame; each shot source has what it needs (a lip-sync shot no video prompt, a chained shot no keyframe prompt, every layer renderable); continuity references exist; lip-sync shots checked in both kinds; one validated storyboard feeds every consumer; the agent is the only writer; the contact sheet with keyframes on the board. Amends 0005 and 0016. |
| [0041](0041-generation-funnel.md) | Proposed: every generation goes through runBatch; model roles in configuration, changed only by the agent; a worst-case budget check per batch (the queue is guarded by the project budget); one workspace cache keyed by content; planned spend equal to the manifest; no double charge on a retried submission; provider rules in adapters and model roles; capabilities as the code has them. Amends 0006, 0014 and 0017. |
| [0042](0042-series-and-episode-audio.md) | Proposed: every series has a budget that commits the canon's spend and every episode budget, checked on creation, budget changes and canon generations; one episode per number; episode settings copied once; episodes add to the canon and never overwrite it; the script validated whole and written only by the agent; the take registry decides what is generated, and a take goes stale on its text, direction or the speaker's reference voice; the episode track is constructed from the takes; German speech and English subtitles as they are. Amends 0016. |
| [0043](0043-bibles-and-character-identity.md) | Proposed: the bibles and the character library are two contexts that exchange copies only; a character's identity always travels on use, its states only when chosen and with the states they derive from; every recurring on-screen character has a sheet; character ids unique and script-id shaped; the canon append-only for episodes; one import rule for music videos and series canons; every library file named; one resolution of continuity references; the set bible an output of style-character; file locks for the library, use and user references. Amends 0025 and 0034. |
| [0044](0044-render-records-and-composed-images.md) | Proposed: one composition renders every format at its size and the master's frame rate, derivatives rendered again with focus points; a render record of the inputs (props, song, asset files, renderer code) decides when a render is current for release, QA and Shorts; previews never recorded and never over a render; a Short belongs to the 9:16 render it was cut from; one command for every composed image with its recipe; determinism per machine and pinned version, checked on every QA pass; every new project and series canon in the media directory; one render per project at a time. Amends 0007 and 0018. |
| [0045](0045-release-records-and-fixed-release-day.md) | Proposed: the release folder, the release calendar and the release status each have one writer, and fixing a release day is the one write into `project.yaml`; the user fixes a proposed release day without approving the autopilot; a refresh never removes a file it could not refresh; `release` and QA run one set of checks, TODO for user gaps; one layout for folder and board, the live URL in every text; a new release day plans every event again, done marks stay, a colliding user day is reported; the approval covers one day, not the content, with its blockers checked everywhere; the microsite data is a published language; English the one built-in language. Amends 0019, 0024, 0028 and 0029. |
| [0046](0046-publishing-records-and-never-twice.md) | Proposed: the publish log, the autopilot log, the autopilot round and the platform credentials each with its lock, one round per workspace (container or timer, never both); publish (an upload that stays private) and post (public at a calendar time) as two adapter families; the autopilot state derived, a take-over a mark in the release status; never twice on every platform, fatal and plain failures, missed posts, one TikTok switch; withdrawing stops what the autopilot has not sent and the board shows the rest; one readiness rule; posting cost shown apart from the generation budget; Instagram's files on fal.ai storage; a named time zone for the board container. Amends 0023, 0029 and 0031. |
| [0047](0047-workspace-marker-and-visible-conflicts.md) | Proposed: the workspace marker is the workspace's identity, written only by init and update; the baseline is upstream's last offer, every runtime file decided by baseline, workspace and new runtime; a conflict stays visible until resolved and update names the user's own changes; the user's paths, `--force` for overwrites and downgrades, a plain update records a missing baseline; one runtime version; only what a workspace can run ships, the upstream CI stays upstream; the npx CLI owns init and update; the board image per workspace, and update says when `docker/` changed. Amends 0010 and 0012. |
| [0048](0048-bench-in-the-workspace.md) | Proposed: the workspace is the model bench's host and takes the fixtures from its own projects; a user's cases are workspace content, upstream ships the mechanism and generic example cases; `bench/`'s configuration and cases add-only for `update`, shipped before any case leaves upstream; a rerun with the run id fills the gaps; one batch cap for the run and each generation, a dry run over budget lists its plan; bench scores are not verdicts, the rubric replaces the usual axes, ratings reach the run folder. Amends 0020. |
| [0049](0049-board-shell.md) | Proposed: the board's shell is a host without state – every write goes to the context that owns it, a view's routes live in its own module, the server file named for the board; the user refreshes by hand, no polling, and a refresh never discards typing; every request needs a loopback Host, reads too; the release folder follows the dot-file rule; the page gets its own content security policy; 400 for malformed input, 404 for unknown names; the navigation can fold away released projects. Amends 0030. |
| [0050](0050-retire-desktop-review-player.md) | The desktop review player is retired; the board is the only writer of review notes, and notes the player left behind go out with the next round. Supersedes 0022. |
| [0051](0051-memes-and-the-sound-library.md) | Proposed: memes are a third project kind (9:16, at most 30 s) on the episode's script, takes and episode track, now the Scripted audio context; the wizard takes a pitch as the starting point of the `new-meme` grilling, not a decision; style and characters after the script; a workspace sound library in `library/sounds/`, a chosen sound copied into the meme as a take and stale when the library sound changes; an unknown licence is a release TODO. Amends 0033. |
| [0052](0052-set-library.md) | A workspace set library in `library/sets/`, on the character library's rules; sets come in where characters do, a use copies the references and every plate; props stay out; character and set library are one Library context, the sound library stays its own. Extends 0034. |
