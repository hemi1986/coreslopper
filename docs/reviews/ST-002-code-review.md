# Code review – ST-002: Edit a library sound's description
Base: main · Commits: 2 · Date: 2026-11-22

Scope: `updateLibrarySound` in `packages/cli/src/sound-library.ts`, `sound edit` in `packages/cli/src/index.ts`,
the `sound edit` block in `tests/sound-library.test.ts`. `check-language.ts`: OK. `tests/sound-library.test.ts`: 13 passed.

What holds: the invariants are enforced in the command function, not only at the CLI. Empty title and use when are refused. Cue and trim are checked against the measured length through the shared core rule `librarySoundTimeProblems`. A typed length or loudness is refused before anything is read. A refused edit throws before the only write. That write goes through `writeTextAtomic` (temp file plus rename), so a refused edit leaves `sound.yaml` unchanged. The id goes through `checkId`, so a path in `<id>` is refused. The file is never touched, and the first scenario checks this with an independent hash. There is no event journal in this repository (conventions, "Commands and events"), so writing `sound.yaml` is the update.
