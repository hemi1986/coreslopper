# Code review – ST-003: Remove a library sound
Base: main · Commits: 4 · Date: 2026-11-23

The three scenario tests exist with their exact titles and pass (`tests/sound-library.test.ts`, 39/39;
`tests/meme-voice-track.test.ts`, 7/7). `npm run typecheck` and `check-language` are green. There is no event
journal in this repository (conventions, "Commands and events"), so the journal and transaction criteria do not
apply; the command is a CLI command over files, like the character library's.

The second, bug-focused pass over the command layer produced #1–#3 and #7: the removal refuses entries that do
not parse, is not atomic on failure, and silently destroys the licence of a sound a meme took.

Checked and found sound:
- **Scenarios.** All three titles are verbatim, the Then of each is really asserted (list, folder gone, take present and current, refusal message), and no test reaches into internals: they go through `removeLibrarySound` / `listLibrarySounds` / `voiceTrack`.
- **HS-260.** Removal touches nothing outside `library/sounds/<id>`; the new test proves the take registry and the take file are byte-unchanged and only `console.warn` speaks (`voice-track.ts:144`). The release check already degrades a missing entry to a TODO (`core/src/release.ts:335`), so removal never breaks a release run.
- **Language.** Library Sound, Sound Library, Take, Take Registry, Meme, Use when and Sound Cue are used as in `docs/glossary.md`; no `_Avoid_` word ("sample", "SFX folder", "soundboard") in the function, the description or the message. `check-language` is green.
- **Architecture.** The command sits in the CLI module that owns the library, imports no other module's internals, and names `CMD-RemoveLibrarySound` / `EVT-LibrarySoundRemoved` at the seam. No time rule, no clock, no read-model change; the read model derives `used_in` on read, so it is right again after a removal.
- **Scope.** No board route, no takes cleanup (#1 of the story's Out of Scope), no documentation page (ST-017 owns it). The extra CLI test is wiring, not new behaviour; `BACKLOG.md` and the story's `status` change are the workflow's, not findings.
- **Success path.** A valid entry is deleted completely (entry and WAV), the returned sound is what `EVT-LibrarySoundRemoved` carries, and a missing WAV on a valid entry can be removed as `sound check` asks.

**Verdict: fix blockers first.**
The most important finding is #1: `sound remove` refuses any entry whose `sound.yaml` does not load, so a hand-broken entry — and every folder a failed removal (#2) leaves behind — can only be removed with `rm -rf` by hand.

## Resolution (main session, 2026-11-23)

- **#1 fixed.** `removeLibrarySound` now decides by the folder's presence (`checkId` plus `existsSync`), loads the entry best effort and returns `sound?: LibrarySound`. Tests: an entry whose `sound.yaml` does not load, and a folder that never held an entry, are removed.
- **#2 fixed.** The folder is renamed to `library/sounds/.removing-<uuid>` first, then deleted; a failed delete throws a typed `ValidationError` naming the hidden leftover, and the library no longer lists the id. Test: a read-only child directory leaves one `.removing-` folder and a consistent library (skipped as root).
- **#3 (a) done, (b) handed over.** `sound remove` returns `used_in` (`soundUses`) and the command warns, naming the memes that keep their take and that the licence and credit left with the sound. Whether the release TODO should offer a remedy that also works for a missing entry is a developer decision, recorded in the wrap-up.
- **#4 done** (tests for both failure paths), **#5 done** (traversal ids and `Vine Boom` refused, siblings survive), **#6 done** (ST-011's test now removes through the command and keeps the warning assertion; ST-003's test asserts the take registry entry and the take bytes).
- **#7 noted, not fixed.** The rename narrows the racing-`sound edit` window but cannot close it while library writes stay unlocked (G-130); a per-id lock is a library-wide decision, not this story's.
